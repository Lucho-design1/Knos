# Slop audit: AI agent pull requests against Knos's checks

**In plain words.** We took a public list of pull requests that AI coding agents opened on GitHub. We ran the checks Knos runs on each one that a diff or GitHub's own record can show. Every number below is counted, with its sample size, and the code to count it again is in this repository.

Generated by `python -m research.slop_audit` (code in `research/slop_audit/`, output in
`research/slop_audit/out/slop_audit.json` and `.csv`); checked by `tests/test_slop_audit.py`, which also checks that
every "k of n (p%)" on this page is a share in that output.

## Data

- **Dataset:** AIDev, `hao-li/AIDev` on Hugging Face, tag **v4** (revision `bc7996907b404359f581c43d5160afe6ed599a14`,
  "AIDev-2.7M", cutoff Nov 2025 per its dataset card). Tables used: `pull_request` and `pr_commit_details` of
  **AIDev-pop** (agent pull requests in repositories with more than 100 stars; created 2024-12-24 to 2025-10-24).
  Issue links come from tag **v3** (revision `3ca0045773097b138b064550dfd6e72229f40bee`, table `related_issue`),
  because v4 dropped that table. The sha256 of each file read is in the output's `meta`.
- **Papers:** H. Li, H. Zhang, A. E. Hassan, "The Rise of AI Teammates in Software Engineering (SE) 3.0: How Autonomous
  Coding Agents Are Reshaping Software Engineering", arXiv:2507.15003 (2025); and "AIDev: Studying AI Coding Agents on
  GitHub", arXiv:2602.09185.
- **Licence:** the dataset is CC BY 4.0; each source repository keeps its own licence for its code, patches and text.
  Nothing from the dataset is committed here: only counts.
- **GitHub's record:** read on 13 Oct 2026, read-only, for the pull requests that claim tests pass or CI is green.

## Results

Agents: OpenAI Codex, GitHub Copilot, Cursor, Devin, Google Jules, Claude Code. 71,677 pull requests; 69,654 have a
file list in the dataset.

| measure | all agents |
|---|---|
| description claims tests pass or CI is green | 7,608 of 71,677 (11%) |
| of those with a finished CI verdict (passed or failed), a check failed at the head commit | 1,119 of 3,736 (30%) |
| the same, out of every claimant whose record was read | 1,119 of 7,608 (15%) |
| changes at least one test file | 32,425 of 69,654 (47%) |
| merged with no test file changed | 25,744 of 48,379 (53%) |
| says tests were added, changes no test file | 1,219 of 11,135 (11%) |
| fires at least one static cheat rule | 6,866 of 69,654 (10%) |
| **fails at least one measured Knos check** | **8,954 of 69,654 (13%)** |
| of those, merged anyway | 6,059 of 8,954 (68%) |

Of the 7,608 claimants, GitHub's record at the head commit was: 2,617 passed, 1,119 failed, 3,334 had no check at
all (a claim nothing can confirm), 104 pending, 7 awaiting approval, 112 other (cancelled, stale), 315 unreadable
(repository gone or private, or more than 100 checks).

**False "tests pass" / "CI is green" claims, by agent** (of claimants with a finished verdict): Copilot
955 of 3,274 (29%), Claude Code 102 of 300 (34%), Devin 36 of 110 (33%), Cursor 21 of 33 (64%), OpenAI Codex
5 of 17 (29%), Google Jules 0 of 2 (0%).

The last four rest on small numbers: read the intervals in the JSON.

**Static cheat rules** (each out of the pull requests with a file list). A test file deleted 3,912 of 69,654 (5.6%).
A skip, xfail or `.only` marker added 1,696 of 69,654 (2.4%). An existing test file lost more assertions than it
gained 1,393 of 69,654 (2.0%).

A CI file gained a way to pass whatever happens 681 of 69,654 (1.0%). A CI file lost a
step that runs the tests 228 of 69,654 (0.3%).

**Issue-linked pull requests** (links from v3): 4,905 pull requests link one of 4,577 issues; 2,375 of 4,905 (48%)
were merged, and 774 of 4,585 (17%) with a file list fail a measured check. On 104 issues one agent pull request was
merged and another was not; on 64 of them the merged fix changed tests.

Those tests could judge the 117 unmerged
attempts as hidden tests: that is the size of the executed benchmark this data allows (see Limitations).

## Method

1. **The pull requests.** Every pull request of AIDev-pop v4. Changed files come from `pr_commit_details` (per
   commit: path, status, patch), read with DuckDB in two passes so the patch column is read only for test and CI files.
2. **What the description claims.** Read by Knos's own reader, `knos.proof.claims.read`, the one the gate and
   `knos_check_pr` use: "tests pass" and "CI is green", with hedges ("should pass", "once CI runs"), HTML comments,
   quoted prompts and unticked task-list boxes set aside. "Says tests were added": a sentence with a verb of adding and
   the word test(s), with the same hedge words set aside.
3. **GitHub's record.** For all 7,608 claimants (no sampling), the head commit's check runs and commit statuses, read
   with one read-only GraphQL query per 20 pull requests: the same query and verdict as the Agent PR Index
   (`scripts/agent_pr_ci.py`). "Failed": a project check, not the agent's own session run, concluded failure,
   timed_out or startup_failure.
4. **Static cheat rules** (`research/slop_audit/rules.py`): the part of the gate's cheat library a diff alone can show
   (test file deleted, assertions removed from an existing test, skip/xfail/`.only` added, CI made unable to fail,
   CI test step removed).
5. **"Fails a measured Knos check"**: a false claim (3), or "says tests were added" with no test file changed (2), or
   any static cheat rule (4).

Every share has a Wilson 95% interval in `slop_audit.json`.

## Limitations (read before quoting a number)

- **No hidden tests were run.** The launch plan's measure (run the tests of the fix that was finally merged against
  each failed agent attempt) needs each repository built at each attempt; that was not done in this run. The data
  allows it for the 117 attempts on 64 issues counted above.
- **The cheat rules are signals, not verdicts.** A maintainer may delete an obsolete test or skip a flaky one on
  purpose. Each rule is a pattern on the diff, tested on known cases in `tests/test_slop_audit.py`.
- **The CI record is read now, not at merge time.** A re-run can change it; a repository can disappear (`error`).
  "No CI" is never counted as passed.
- **Patches can be missing.** GitHub's API leaves large patches out, so a large test change may go unread.
- **Test files are found by path** (tests/, `test_x.py`, `x.test.ts`, `XTest.java` ...). Tests inside source files
  (Rust `#[cfg(test)]`) are under-counted.
- **AIDev-pop only**: repositories with more than 100 stars, to the dataset's cutoff. Agents differ widely in how many
  pull requests they have here, and Codex descriptions rarely make a test claim (102 of 35,521).
